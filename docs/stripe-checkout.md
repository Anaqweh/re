# تفعيل Stripe للدورات

الربط مخصص لنظام التسجيل الحالي في PostgreSQL. لا يستخدم وظائف Supabase القديمة.
يحسب الخادم سعر الدورة والشهادة من قاعدة البيانات بالدرهم، وينشئ صفحة دفع Stripe.
لا يتحول الطلب إلى «مؤكد» إلا بعد التحقق من العملية لدى Stripe ومطابقة المبلغ والعملة والطلب.
إعادة محاولة الطلب تستخدم مفتاحًا ثابتًا لمنع إنشاء عملية دفع ثانية للطلب نفسه.

## التفعيل على خادم API الحالي

شغّل الملف `scripts/deploy-stripe-checkout.py` من **طرفية الخادم**، مع رقم commit كامل من هذا المستودع:

```bash
python3 /tmp/deploy-stripe-checkout.py FULL_COMMIT_SHA
```

نزّل الملف نفسه من الـcommit الذي ستنشره. مجلد الخدمة الافتراضي `/opt/inexc-training/inexc-api`؛
يمكن ضبط `INEXC_API_DIR` لمجلد آخر. يتطلب Python 3 وDocker Compose وcurl وصلاحيات ملفات الخدمة وDocker.
يشترط ملف Compose تقليدي واحد وخدمة باسم `api`. يحتفظ بإعدادات الخدمة الحالية.
إذا وُجد override غير تابع لهذا المثبّت، يتوقف دون الكتابة فوقه؛ أضف متغيرات الخدمة يدويًا في تلك الحالة.

يطلب المثبّت مفتاح Stripe الحي بإدخال مخفي، ويتحقق أن الحساب يسمح بتحصيل المدفوعات.
لا ترسل المفتاح في الدردشة أو تضعه في رابط أو أمر ظاهر. يُستخدم فقط في ملف `.env` على الخادم بصلاحية `600`.
لا تحتاج الواجهة إلى مفتاح عام لأن الدفع يتم على صفحة Stripe المستضافة.

ينشئ المثبّت webhook لهذا العنوان إذا لم يكن موجودًا:

`https://api.inexctraining.com/api/payments/stripe/webhook`

الأحداث المطلوبة:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`

عند وجود endpoint سابق، يعيد استخدام سر التوقيع المحلي أو يطلب `whsec_` بإدخال مخفي من لوحة Stripe.
يجب أن يكون endpoint مفعّلًا ويستقبل الأحداث الأربعة. لا يغيّر webhooks الأخرى.
مفتاح API المقيّد يحتاج قراءة الحساب، وقراءة/إنشاء/إنهاء جلسات Checkout، وصلاحيات webhooks للمثبّت.
عند استعمال أسعار ومنتجات مضمّنة، افحص أيضًا صلاحيات Products وPrices. فحص الجلسة يعرض رموز الصلاحيات الناقصة التي يعيدها Stripe (`rak_*`) دون عرض المفتاح أو نص خطأ مزود الخدمة كاملًا.

المتغيرات المحفوظة في `.env` والممررة إلى حاوية `api`:

```dotenv
STRIPE_SECRET_KEY=LIVE_SECRET_FROM_STRIPE
STRIPE_WEBHOOK_SECRET=SIGNING_SECRET_FROM_STRIPE
STRIPE_CHECKOUT_ENABLED=1
```

المثبّت يأخذ نسخة خاصة من الإعدادات، وينشر نسخة API المثبتة بالـcommit، ويتحقق من جاهزية الخدمة ووجود إعدادات Stripe. هذا وحده لا يثبت نجاح إنشاء جلسة دفع.
عند فشل النشر يعيد الملفات والصورة السابقة وإعدادات الدفع. لا ينشئ تسجيلًا أو يدفع مبلغًا أو يرسل بريدًا للاختبار.
احمِ نسخ `stripe-activation-backup-*` مثل ملف `.env`؛ فهي تحتوي إعدادات الخادم.

## التحقق والتشغيل

```bash
curl --fail https://api.inexctraining.com/api/payments/stripe/capabilities
```

تعني `enabled: true` أن إعدادات Stripe موجودة؛ لا تعني اختبار إنشاء جلسة أو تحصيل حي. يعيد التحديث الجديد `version: 2` و`perCourse: true` أيضًا.
بعد التفعيل افتح `/register/` وحدد دورة؛ يظهر «الدفع بالبطاقة عبر Stripe» إذا فعّله المدير لهذه الدورة، ولا يطلب إيصالًا.
العودة من Stripe تعرض صفحة متابعة تتصل بالخادم؛ لا تعتمد على معاملات رابط «نجاح» لتأكيد الدفع.
كل طريقة تظهر وفق اختيار المدير للدورة.

## إدارة جميع الدورات من لوحة المدير

لخادم أُدخلت فيه مفاتيح Stripe بالفعل، نزّل `scripts/deploy-course-payments.sh` من commit كامل، ثم شغّله مع الرقم نفسه. لا يعيد طلب المفاتيح. يحتفظ بنسخة من ملفات API السابقة ويشغّل فحص إنشاء جلسة داخلية وإنهائها فورًا؛ لا ينشئ متدربًا أو تسجيلًا أو دفعة أو بريدًا.

الانتقال الأول يضيف Stripe لجميع الدورات الحالية، المنشورة والمخفية، دون تغيير بيانات البنك أو الأسعار أو الشهادات أو حالة بطاقة INEXC. تتخلف الدورات الجديدة إلى Stripe والبنك وبطاقة INEXC؛ يستطيع المدير تعديل هذا الاختيار من الشاشة نفسها. إعادة تشغيل الخدمة أو إعادة نشرها لا تعيد تفعيل طريقة أوقفها المدير.

افتح `/admin-portal.html#payments` بعد تسجيل الدخول:

- زر «تفعيل Stripe لجميع الدورات» يضيف Stripe ويحتفظ بالطرق الأخرى.
- الاختيار الموحد يستبدل طرق جميع الدورات باختيار المدير: طريقة أو طريقتان أو ثلاث أو لا شيء. يمكن اعتماده للدورات الجديدة أيضًا.
- كل صف يتيح حفظ طرق دورة واحدة. الخيارات نفسها موجودة في نموذج إضافة/تعديل الدورة.
- الطرق: Stripe، تحويل بنكي، بطاقة INEXC، ورابط خارجي اختياري. الرابط الخارجي يحتاج HTTPS محفوظًا لكل دورة، ولا يصلح افتراضيًا لدورات لم يُدخل رابطها بعد. Stripe لا يحتاج رابطًا يدويًا.
- إلغاء جميع الطرق يوقف دفع الدورات المدفوعة بهذه الطرق، ولا يوقف التسجيل المجاني لدورة سعرها صفر.
- رسوم الشهادة الاختيارية مع بطاقة INEXC تُسدّد بنكيًا في النظام الحالي. عند إيقاف البنك، يُرفض هذا المسار دون خصم رصيد؛ يمكن التسجيل دون الشهادة أو اختيار طريقة دفع أخرى للدورة والشهادة.

الحفظ والفحص يتطلبان جلسة مدير صالحة. الخادم يرفض طرق الدفع المعطّلة حتى لو حاول العميل إرسالها يدويًا. العمليات التي أُنشئت بالفعل لدى Stripe لا تُلغى عند تغيير خيارات الدورة؛ تبقى webhooks قادرة على مطابقة نتيجة الدفع وتأكيدها.

زر «فحص إنشاء صفحة الدفع» يتحقق من السماح بالتحصيل ثم ينشئ جلسة حية داخلية باسم فحص جاهزية INEXC، ببيانات خدمة فقط، ويغلقها فورًا. لا يعرض رابطها ولا يرسلها إلى عميل. لا يمثل الفحص اختبار تحصيل أو إثباتًا لوصول webhooks. يبقى تأكيد التسجيل مربوطًا بالتحقق الموقّع ومطابقة المبلغ والعملة. إن فشل الفحص، يبقي سكربت النشر لوحة التحكم مثبتة ويخرج بالرمز 2 مع تشخيص آمن؛ صحّح إعداد Stripe ثم أعد الفحص من لوحة المدير.

يستخدم الربط Stripe API `2026-08-26.dahlia` وطرق الدفع الديناميكية. تبقى العملة AED دون Adaptive Pricing، حتى يطابق المبلغ المسجل في قاعدة البيانات قيمة الدفع.

لتعطيل **إنشاء عمليات جديدة** غيّر `STRIPE_CHECKOUT_ENABLED=0` في `.env` وأعد إنشاء حاوية API.
أبقِ المفاتيح والـwebhook لتأكيد العمليات التي بدأت سابقًا. يظل إلغاء تسجيل إداري محفوظًا حتى لو وصل دفع متأخر.
الاسترداد المالي وإلغاء المدفوعات يتمان من Stripe ولا ينفذهما هذا الربط تلقائيًا.

الاختبارات المحلية تستخدم Stripe وهميًا وPostgreSQL معزولًا وDOM محليًا. لا تمثل اختبار تحصيل حي.
التفعيل الحي لا يكتمل بمجرد رفع الكود؛ يلزم تنفيذ خطوة الخادم والتحقق من حساب Stripe.
